== what is concurrency

Concurrency in computer science refers to the **ability of different parts of a program to execute independently and simultaneously**. +

It enables multiple computations to progress at the same time, either by allowing different parts of a program to be **executed out of order** or simultaneously on multiple processors. +

This concept is fundamental to modern computing, where systems need to handle multiple tasks efficiently, respond to various events, and maximize the use of available computing resources. +

Concurrent programming allows applications to remain responsive while performing time-consuming operations, handle multiple user requests simultaneously, and take **advantage of multi-core processors for improved performance**.

== why concurrency matters

Concurrency has become increasingly important in modern software development for several reasons.
Modern hardware architectures feature multiple processing cores, making concurrent programming essential for utilizing the full potential of available computing resources.
Applications need to remain responsive while performing complex calculations or I/O operations, which is achieved through concurrent execution.
In distributed systems and web applications, concurrency enables handling multiple user requests simultaneously, improving scalability and user experience.
Additionally, certain problems naturally lend themselves to concurrent solutions, such as simulation systems, real-time data processing, and parallel algorithms, where concurrent execution can significantly improve performance and efficiency.

== happens before relation

When we say "A happens before B" +
it means that all *actions* and *memory changes* +
in A are guaranteed to be visible to B

=== !

If thread 1 writes to a variable and thread 2 reads it later, without proper "happens before" relationship, thread 2 might see an old/stale value

=== !

This is why we can't just use regular variables shared between threads - they don't establish "happens before" and are not immune to hardware optimizations and memory ordering for your CPU

=== !

* Java Memory Model defines pairs of actions that establish "happens before" relationship
** volatile write followed by volatile read
** synchronized enter and exit
** lock acquire and release

=== object pool

A thread-safe object pool implementation with minimum and maximum capacity. +
The pool auto-creates objects up to maximum capacity and maintains minimum number of valid objects. +
Invalid objects are replaced to maintain minimum capacity.

=== implementation

Objects are managed using a BlockingQueue and Semaphore to control concurrent access. +

=== actor model

The Actor Model is a conceptual framework for building concurrent systems where actors serve as the fundamental unit of computation.
Each actor is an independent entity that processes messages asynchronously through its dedicated mailbox, which acts as a message queue.
Actors communicate exclusively by sending messages to each other's mailboxes, never sharing state directly.
When an actor receives a message, it can perform local computations, create new actors, send messages to other actors, or modify its own internal state.
This message-passing approach naturally enforces isolation and encapsulation, making concurrent systems easier to reason about and less prone to traditional concurrency issues like deadlocks and race conditions.
The model achieves concurrency through parallel message processing, where multiple actors can process their respective messages simultaneously without interfering with each other.
